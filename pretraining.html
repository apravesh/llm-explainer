Learn to predict.
One token at a time.

Pretraining builds a base model from large text collections. Prepare the data, turn it into token IDs, then repeatedly use prediction errors to adjust the model’s weights.

01 / DATA

The web is a starting point.
Not a ready-made dataset.

Crawlers fetch pages and follow links, producing snapshots such as Common Crawl. A training pipeline extracts text, reviews sources, filters low-quality or sensitive content, and removes duplicates. Publicly accessible does not automatically mean appropriate or licensed for training. [1, 2]

A miniature corpus7 hand-authored records · no websites fetched

What happens at real scale?

Corpora can combine crawls with licensed, curated, code and other sources. Deduplication includes near-matches; quality/privacy filtering is imperfect and needs evaluation. Hold-out splits and contamination checks help avoid evaluating on memorized training text. Tokenized sequences are shuffled or sampled from storage shards; mixture weights determine how much each source contributes. A shard is a storage chunk, not a batch. [2]

02 / TOKENIZER

Build a vocabulary
from recurring pieces.

Byte-Pair Encoding (BPE) starts with small symbols, counts adjacent pairs, and repeatedly merges the most frequent pair. Save the vocabulary and ordered merge rules. Encoding new text applies those rules to produce token IDs; it does not retrain the tokenizer. [3]

    03 / PRETRAINING

    Predict. Measure the error.
    Send gradients backward.

    The text supplies its own targets: predict the next token at each position. A causal mask hides future tokens. Average the token losses across the batch, backpropagate that one loss, then update shared weights. Training uses the ground-truth previous tokens—not sampled predictions. [4]

    What is simplified—and what really runs?

    The demo executes embedding lookup, fixed sinusoidal positions, one pre-normalized causal attention head, a tanh MLP, residuals, final normalization and an untied vocabulary projection. Scalar automatic differentiation computes gradients for every learned matrix. For each position, the gradient at a vocabulary logit is (p − one-hot(target)) divided by the number of valid targets in the batch. SGD with learning rate 0.1 performs the update. It omits biases, trainable normalization gains, dropout, weight decay, clipping, mixed precision and a learning-rate schedule. Tanh is chosen for simplicity; modern LLMs commonly use other MLP activations.

    Each displayed batch has five valid targets per sequence; there is no padding or cross-document attention. <bos> begins each sequence. Real training handles many more tokens, padding/loss masks or packed examples, distributed workers and often gradient accumulation. The reported loss is a mean over valid target tokens; natural logarithms give nats. One optimizer step follows the batch average—not one step per token. [4]

    The before/after losses use the same tiny training batch. Repeating it demonstrates fitting, not generalization. A held-out evaluation is needed to assess generalization; a single update is not guaranteed to reduce loss on arbitrary data. This demo does not train its tokenizer or generate text during a model update.
