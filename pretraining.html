01 / DATA

A web page is one long string.
Most of it is not text.

A crawler downloads pages as raw HTML. To a computer each page is just a long string of characters: tags, scripts, menus, and somewhere inside, a few sentences worth learning from. Building a corpus means peeling everything else away, then gluing what is left into one even longer string. [1, 2]

What happens at real scale?

Corpora can combine crawls with licensed, curated, code and other sources. Publicly accessible does not automatically mean appropriate or licensed for training. Deduplication includes near-matches; quality/privacy filtering is imperfect and needs evaluation. Hold-out splits and contamination checks help avoid evaluating on memorized training text. Tokenized sequences are shuffled or sampled from storage shards; mixture weights determine how much each source contributes. A shard is a storage chunk, not a batch. [2]

02 / TOKENIZER

Glue the most common
neighbours together. Repeat.

A model reads numbers, not letters. Byte-Pair Encoding (BPE) starts with every character as its own token, finds the pair of neighbours that appears most often, and fuses it into one new token. Each merge adds one vocabulary entry and makes the text shorter. [3]

Overlapping adjacent pairs are counted; replacements are non-overlapping, left to right; ties use a fixed lexical order. Real tokenizers may start from bytes and use normalization, pre-tokenization and special tokens. Token IDs are labels, not feature values; an embedding table maps IDs to vectors. Encoding new text applies the saved rules; it does not retrain the tokenizer.

    03 / PRETRAINING

    Guess the next token.
    Get corrected. Repeat.

    The text is its own answer key: at every position the model guesses the next token, and the real next token says how wrong it was. That error travels backward through the model and nudges every weight a little. A causal mask stops the model from peeking ahead. [4]

    BATCH LOSS OVER UPDATES

    What is simplified—and what really runs?

    The demo executes embedding lookup, fixed sinusoidal positions, one pre-normalized causal attention head, a tanh MLP, residuals, final normalization and an untied vocabulary projection. Scalar automatic differentiation computes gradients for every learned matrix. For each position, the gradient at a vocabulary logit is (p − one-hot(target)) divided by the number of valid targets in the batch. SGD with learning rate 0.1 performs the update. It omits biases, trainable normalization gains, dropout, weight decay, clipping, mixed precision and a learning-rate schedule. Tanh is chosen for simplicity; modern LLMs commonly use other MLP activations. Training uses the ground-truth previous tokens, not sampled predictions.

    Each displayed batch has five valid targets per sequence; there is no padding or cross-document attention. <bos> begins each sequence. Real training handles many more tokens, padding/loss masks or packed examples, distributed workers and often gradient accumulation. The reported loss is a mean over valid target tokens; natural logarithms give nats. One optimizer step follows the batch average—not one step per token. The gradient strips under each stage show ∂L/∂activation for the selected position, each scaled to its own largest value. [4]

    The before/after losses use the same tiny training batch. Repeating it demonstrates fitting, not generalization. A held-out evaluation is needed to assess generalization; a single update is not guaranteed to reduce loss on arbitrary data. This demo does not train its tokenizer or generate text during a model update.
