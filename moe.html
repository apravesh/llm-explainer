01 / THE ROUTER

The router

After attention, each token has a vector that carries what it gathered from the tokens before it. In the text transformer that vector goes straight into the block's MLP. Here it first goes to a router, which decides which MLPs should handle it.

Step 1 · One score per expert different

The router is one small learned matrix, Wr, with a row for each expert. Multiplying it with the token's vector gives one score per expert: 8 experts, 8 scores. A high score means “this expert suits this token”. No expert has done any work yet.

The router is tiny next to what it steers. In Mixtral it is 8 × 4,096 numbers per block, about 33 thousand, while each expert holds about 176 million.

Step 2 · It reads the vector, not the word

The scores depend on the token's current vector, which attention has already mixed with its context. So the same word can be sent to different experts in different sentences. Each block also has its own router and its own experts, so a token's route changes from block to block. Step through the blocks in the explorer to see it.

02 / TOP-K

Top-k: only some experts run

The router has scored every expert. Now most of them are sent home.

Step 1 · Keep the k best scores different

Only the k highest scores are kept; here, and in Mixtral, k = 2. It is the same top-k filter that picks candidate words at the end of the text transformer, applied to experts instead.

Step 2 · The others do no work

The experts that were not chosen are not run for this token. This is the whole point: they are not computed and then multiplied by zero, they are skipped. Their weights stay in memory and wait for a token that suits them better.

03 / EXPERTS

The experts and the weighted sum

Two experts have been chosen. Each one works on the token's vector, and their two answers are blended into one.

Step 1 · An expert is an ordinary MLP

Each expert has the shape of the MLP on the text page: widen the vector, apply a simple function, narrow it back. What differs is that each expert has its own weights. In Mixtral every expert is a gated MLP like the one on the Vision page, 4,096 → 14,336 → 4,096.

An expert is not a small language model, and nobody assigns it a subject. Whatever each one becomes good at comes out of training, and it is usually hard to put a name on.

Step 2 · Softmax over the chosen different

The two scores that survived top-k go through a softmax, which turns them into two weights that add up to 100%. The expert the router preferred counts for more.

Step 3 · Weighted sum different

Both chosen experts receive the same whole vector, not a piece each, and each returns a vector of the same size. Each output is multiplied by its weight and the two are added, number by number. Nothing is placed side by side, so the result has the same size as the input.

That sum is then added to the token's vector through the residual connection, exactly where the MLP's output would be added in the text transformer. The next block cannot tell that an MoE layer was there.

04 / STORED VS USED

Stored vs used: why this is worth it

In the text transformer, the number of weights the model has and the number it uses for one token are the same thing. An MoE pulls the two apart.

More weights, same work per token

Adding experts gives the model more room to store what it learns, without making each token more expensive: a token still runs the router and two experts, however many experts are waiting. Mixtral 8x7B stores 46.7 billion weights and uses about 12.9 billion for any one token.

What it does not save

Memory. Every expert has to be loaded, because the next token may need it, so an MoE takes the memory of its full size. It also adds the cost of sorting tokens by expert and sending them there and back. An MoE is not automatically faster than a plain model with as many weights as it uses per token. The Parameters chapter works through these budgets.

05 / TRAINING

How an MoE learns

An MoE is trained with ordinary backpropagation and the same next-token loss as a plain transformer. The difference is where the gradient can go: it can only flow back along the path the token actually took.

activations, forwardgradients, backwardweights that get a gradientidle: no work, no gradient

Each expert sees fewer tokens

A single MLP gets a gradient from every token. An expert only learns from the tokens routed to it: with 8 experts and top-2, about a quarter of them if the routing is balanced.

The choice itself has no gradient

Picking the top-k is a hard decision, like rounding. The router learns only through the weights g that scale the chosen experts' outputs. An expert that is never picked can never show that it would have helped.

Balance has to be trained in

Left alone, a few experts win early, get trained more and keep winning. Training usually adds a load-balancing loss, and sometimes a limit on how many tokens one expert may take or a little noise in the routing, to keep all experts in use.

Memory follows all the experts

Each token computes with k experts, but every expert's weights, gradients and optimiser state have to be stored. The experts are usually spread over several GPUs, so tokens are shipped to them and back in both passes.

In words: if an expert's output points the way the loss wants y to move, its weight, and so its router score, is pushed up. Otherwise it is pushed down. Experts that were not chosen are not part of y, so the loss says nothing about them.

Where do the numbers on this page come from? Method, variants and limits

The model in the explorer. The diagram and the “Who gets the work?” table run a small transformer in your browser: width 8, 4 blocks, 2 causal attention heads of 4 numbers, and in each block a router (8 × 8) and 8 expert MLPs (8 → 16 → 8, GELU), of which the top 2 run. Their weights are fixed random numbers and the model was never trained. Each word is one token with a made-up starting vector plus a position vector; there is no real tokenizer. The router scores, the choice of experts, the weights, the attention scores and the weight counts in section 04 are this model's real arithmetic. They show how the mechanism works, not what a trained model would choose: the routes carry no meaning.

What is illustrative. An untrained model cannot predict words, so the list of next tokens on the right of the diagram is a fixed, hand-written list. The vector bars are plain shapes that only show sizes.

Real models. The sizes given for Mixtral 8x7B (32 blocks, 32 heads, width 4,096, experts of 14,336, 8 experts per block with 2 active, 46.7 billion weights of which about 12.9 billion are used per token) are those published by Mistral AI. GPT-2 (small) is the model of the text page. Nothing on this page was recorded from Mixtral.

Variants. The page shows one common design: top-2 routing with a softmax over the chosen experts, as in Mixtral. Other models choose a single expert and weight it by its probability (Switch Transformer), add noise to the scores before choosing, cap how many tokens an expert may take, or keep one shared expert that always runs. The training lab lets you compare three of these rules on its own two-dimensional toy.

What is left out. The explorer does no training, and has no load balancing, capacity limits, dropped tokens or communication between machines. The weight counts ignore normalisation and biases.
