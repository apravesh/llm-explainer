EXPERT ASSIGNMENTS

Real systems batch together the tokens assigned to each expert. Uneven routing can overload some experts and leave others idle. This demo has no capacity limit, token dropping, or load-balancing loss.

PARAMETERS STORED ≠ PARAMETERS USED PER TOKEN

A bigger pool. A smaller active path.

Stored/active counts are scalar parameters. Linear MACs happen to have the same counts for one vector in these bias-free projections. They exclude normalization, activation, selection, memory movement, and communication. MoE is not automatically faster than a single same-width dense MLP.

THE THREE IDEAS TO KEEP

01

An expert is an MLP.

Each expert has the same input/output shape but its own weights. It is not a full language model or a hand-coded “math expert.” Useful specializations emerge through training; our untrained experts have no semantic roles.

02

Routing is per token.

A small learned router scores experts from the current hidden state. Different tokens—or the same token in different contexts and layers—can take different routes. Attention still lets tokens exchange information.

03

Only selected experts run.

Top-1 uses one expert; top-2 uses two and combines their outputs. The result is added to the original hidden state. More stored expert parameters do not mean all of them are evaluated for every token.

TRAINING · SAME BACKPROP, SPARSER PATHS

How does an MoE learn?

An MoE is trained with ordinary backpropagation and the same next-token loss as a dense model. The difference is where the gradient can go: it can only flow back along the path the token actually took.

activations, forwardgradients, backwardweights that get a gradientidle: no work, no gradient

01

Each expert sees fewer tokens.

A dense FFN gets a gradient from every token. An expert only learns from the tokens routed to it — with 8 experts and top-2, roughly a quarter of the batch if routing is balanced.

02

The choice itself has no gradient.

Picking the top-k is a hard decision, like rounding. The router learns only through the gate values gᵢ that scale the chosen experts’ outputs. An expert that is never picked can never prove it would have helped.

03

Balance must be trained in.

Left alone, a few experts win early, get trained more and keep winning (“collapse”). Training adds a load-balancing loss, per-expert capacity limits, sometimes routing noise, and a router z-loss to keep logits small and stable.

04

Memory follows all experts.

Each token computes with k experts, but every expert’s weights, gradients and optimizer state must be stored. Experts are usually spread over GPUs, so tokens are shipped to them and back (all-to-all) in both passes.

router weights∂L/∂Wᵣ = xᵀ · ∂L/∂z

In words: if an expert’s output points the way the loss wants y to move, its gate — and so its router score — is pushed up. Otherwise it is pushed down. Unchosen experts are not part of y, so the task loss says nothing about them.

One mechanism, several design choices.

The default is a minimal GELU-expert, top-2 teaching layer: two experts run and their selected gates are normalized to sum to one. Switching to top-1 selects a single expert with a normalized gate of exactly 1.

The Router inspector also offers keep full-softmax probabilities. Switch Transformer uses top-1 routing with a probability-weighted output; implementations differ in their normalization, capacity, load balancing, and expert architecture. This demo is not a reproduction of Switch or Mixtral. Its four blocks, two attention heads, width 8, LayerNorm, sinusoidal positions and eight-symbol output are deliberately tiny teaching choices.

METHOD & LIMITATIONS

Real arithmetic.
Not a trained model.

A four-block pre-normalized teaching transformer runs locally: hidden width 8, two causal attention heads of width 4, independent Q/K/V/Wₒ matrices and a separate router and four expert MLPs per block. Each FFN has intermediate width 16, LayerNorm before routing, GELU or SwiGLU experts, and a residual. Final LayerNorm and an independent 8 × 8 toy vocabulary projection run after all blocks. SwiGLU adds an independent 8 × 16 projection and uses SiLU plus featurewise multiplication before contraction; this is separate from the router gate.

Token labels are split on whitespace, capped at 12. A deterministic seed based on each label and its position produces an initial eight-dimensional hidden state. Sinusoidal positions are added once before block 1; no RoPE or learned normalization gains/biases are used. You can edit the original seeded values in the input inspector; this recomputes the complete stack. There is no pretrained embedding, language generation, or external API. v0–v7 label symbolic vocabulary slots, not real words.

The default top-k gates are renormalized over selected experts. The alternate full-softmax convention retains their original probabilities. Unselected experts are not evaluated. The dense comparison uses the same attention weights and expert 1 of each block as that block’s FFN, with no routing; it is not an equal-parameter-size dense baseline.

In the explorer, no training, load-balancing loss, capacity limit, dropped tokens, noise, shared expert, or distributed all-to-all communication is simulated. Routing patterns are not evidence of semantic specialization. All math, parameters, and token data remain on your device. The separate training section uses its own two-dimensional toy with four fixed expert vectors.
