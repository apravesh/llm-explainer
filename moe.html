EXPERT ASSIGNMENTS

Real systems batch together the tokens assigned to each expert. Uneven routing can overload some experts and leave others idle. This demo has no capacity limit, token dropping, or load-balancing loss.

PARAMETERS STORED ≠ PARAMETERS USED PER TOKEN

A bigger pool. A smaller active path.

Stored/active counts are scalar parameters. Linear MACs happen to have the same counts for one vector in these bias-free projections. They exclude normalization, activation, selection, memory movement, and communication. MoE is not automatically faster than a single same-width dense MLP.

THE THREE IDEAS TO KEEP

01

An expert is an MLP.

Each expert has the same input/output shape but its own weights. It is not a full language model or a hand-coded “math expert.” Useful specializations emerge through training; our untrained experts have no semantic roles.

02

Routing is per token.

A small learned router scores experts from the current hidden state. Different tokens—or the same token in different contexts and layers—can take different routes. Attention still lets tokens exchange information.

03

Only selected experts run.

Top-1 uses one expert; top-2 uses two and combines their outputs. The result is added to the original hidden state. More stored expert parameters do not mean all of them are evaluated for every token.

One mechanism, several design choices.

The default is a minimal GELU-expert, top-2 teaching layer: two experts run and their selected gates are normalized to sum to one. Switching to top-1 selects a single expert with a normalized gate of exactly 1.

The Router inspector also offers keep full-softmax probabilities. Switch Transformer uses top-1 routing with a probability-weighted output; implementations differ in their normalization, capacity, load balancing, and expert architecture. This demo is not a reproduction of Switch or Mixtral.

METHOD & LIMITATIONS

Real arithmetic.
Not a trained model.

A single sparse feed-forward sublayer runs locally: width 8, four expert MLPs, expert hidden width 16, a bias-free 8 × 4 router, LayerNorm before routing, GELU or SwiGLU inside each expert, and a residual connection. SwiGLU adds an independent 8 × 16 projection and uses SiLU plus featurewise multiplication before contraction; this is separate from the router gate.

Token labels are split on whitespace, capped at 12. A deterministic seed based on each label and its position produces an initial eight-dimensional hidden state. You can edit its values in the input inspector. There is no pretrained embedding, attention computation, language generation, or external API.

The default top-k gates are renormalized over selected experts. The alternate full-softmax convention retains their original probabilities. Unselected experts are not evaluated. The dense comparison runs expert 1 as a standalone same-width MLP, with no router; it is not an equal-parameter-size dense baseline.

No training, load-balancing loss, capacity limit, dropped tokens, noise, shared expert, or distributed all-to-all communication is simulated. Routing patterns are not evidence of semantic specialization. All math, parameters, and token data remain on your device.
