01 / THE BASICS

The basics

Words you meet in the first five minutes.

LLM Large language model
A program trained on a huge amount of text to predict the next word. Repeating that one step produces sentences, answers and code. Overview →
Token
The unit a model reads and writes: a word or a piece of a word. “empowers” is two tokens, “em” and “powers”. Tokenizer →
Tokenization
Cutting text into tokens before the model sees it. Most models use BPE (byte-pair encoding), which builds tokens by merging the letter pairs that occur most often. Tokenizer →
Token ID
The number assigned to a token. The model only ever sees these numbers, never the letters.
Vocabulary
The fixed list of all tokens a model knows. GPT-2 has 50,257.
Prompt
The text you give the model. Everything it writes is a continuation of it.
Context window
The most tokens a model can read at once, prompt and answer together. Anything beyond it is not seen.
Weights Parameters
The numbers inside the model that training adjusts. “A 7B model” has seven billion of them. Parameters →
Training
Teaching the model from examples where the answer is known, by adjusting its weights until its guesses improve. Pretraining →
Inference
Using a trained model to produce an answer. Only the question is known, and the weights do not change.
Hallucination
A fluent answer that is wrong or made up. The model predicts likely text; it does not check facts.
Modality
A kind of input or output: text, image, audio or video. A multimodal model handles more than one.
Open and closed models
An open model publishes its weights so anyone can download and run it. A closed model can only be used through the maker’s app or API.

02 / INSIDE THE MODEL

Inside the model

The parts of a transformer, in the order data passes through them.

Transformer
The architecture behind almost every LLM: a stack of identical blocks, each made of attention followed by an MLP. Transformer →
Embedding
Turning a token (or an image patch) into a list of numbers, a vector, that the model can compute with. Embedding →
Positional embedding
Extra numbers added to each token’s vector that say where it sits in the sentence. Without them word order would be lost. Embedding →
Attention
The step where each token looks at the other tokens and takes in information from the ones that matter to it. Self-attention →
Query, Key, Value Q, K, V
Three vectors every token makes for attention. Query: what am I looking for. Key: what do I offer. Value: the information handed over when a Query matches a Key. Self-attention →
Attention head
One of several attention calculations run side by side in a block. Each head learns to look for something different. Self-attention →
MLP Multi-layer perceptron
The second half of a block. It reworks each token on its own: widen the vector, apply a simple function, narrow it back. MLP →
Residual connection
Adding a step’s input back to its output, so each block adjusts the vector instead of replacing it.
Output projection
The last layer. It turns the final vector into one score for every token in the vocabulary. Probabilities →
Logits
Those raw scores, before they are turned into probabilities. Probabilities →
Softmax
The formula that turns scores into probabilities that add up to 100%. Probabilities →
Temperature
A setting that makes the choice of next token safer (low) or more varied (high). Probabilities →
Top-k and top-p
Two ways to drop unlikely tokens before choosing: keep the k best, or keep the best ones until their chances add up to p. Probabilities →
Dense model
A model where every token passes through all of the weights in every block. MoE →
MoE Mixture of experts
A model where each block holds several MLPs (“experts”) and a small router sends each token to only a few. More weights in total, but only part of them used per token. MoE →
Vision encoder
The part of a model that cuts an image into patches and turns them into vectors the language model can read. Vision →
VLM Vision language model
A model that takes images and text as input and writes text. Vision →
Diffusion
The architecture used by most image and video generators. It starts from noise and removes it step by step. It is not an LLM.

03 / TRAINING

Training

How a model goes from random numbers to something useful.

Pretraining
The first and largest stage: learning to predict the next token on huge amounts of raw text such as web pages, books and code. Pretraining →
Mid-training
An optional middle stage on cleaner text from one field, for example mostly code for a coding model.
Post-training
The later stages on smaller, carefully built data that turn a text predictor into an assistant. Instruct →
Fine-tuning
Any further training of an already trained model on new data. Post-training is fine-tuning done by the model’s maker.
Instruction tuning SFT, supervised fine-tuning
Post-training on question and answer pairs. The model is graded only on the answer part. Instruct →
RL Reinforcement learning
Post-training where the model tries answers, the answers are scored, and it is nudged towards the better ones. REINFORCE, GRPO and DPO are methods for this. RL →
Special tokens
Reserved tokens that mark structure, not words: where a turn begins, where the answer ends (EOS, end of sequence), where thinking starts and stops. Chat format →
Chat template
The fixed layout, built from special tokens, that turns a conversation into one long text the model can continue. Chat →
Synthetic data
Training data written by another model instead of by people.
Curriculum
The order in which data is shown: simpler examples first, harder ones later, like school years.
Loss
A number that says how wrong the model’s guesses are. Training tries to make it smaller. Training loop →
Loss curve
A chart of the loss over time. It should fall and then flatten; spikes or a rise point to a problem.
Backpropagation
The calculation that works out how each weight should change to reduce the loss. Training loop →
Learning rate
How large each adjustment to the weights is. It usually starts higher and is lowered as training goes on.
Optimizer
The rule that applies the adjustments. AdamW is the usual choice for LLMs.
Batch
The group of examples the model sees before each adjustment.
Epoch
One full pass over the training data.
Checkpoint
A saved copy of the weights at one moment in training. Checkpoints →
Distillation
Training a small model to copy the answers of a large one.
W&B Weights & Biases
A widely used tool for recording training runs and viewing their loss curves.

04 / USING MODELS

Using models

What gets built around a model once it is trained.

RAG Retrieval-augmented generation
Search first, then answer. Retrieval: fetch relevant pages or documents. Augmented: paste them into the prompt. Generation: the model answers using them. It is built around the model, not inside it. Web search →
Agent
A model that is given tools and works in a loop: decide a step, run it, read the result, decide the next. Use cases →
Tool calling
The model writes a structured request, such as a search or a command, and the app around it runs the request and returns the result.
Harness
The program around an agent’s model that runs its tools, feeds results back and keeps the loop going.
System prompt
Instructions placed before the conversation that set how the model should behave.
Thinking Reasoning
Letting the model write out its working first, between special tokens, and then the answer. The working is often hidden from the user.
OCR Optical character recognition
Turning a picture of text, such as a scanned page, into real text.
YOLO You Only Look Once
A family of fast vision models that find and box objects in an image. Not an LLM.

05 / HARDWARE AND RUNNING MODELS

Hardware and running models

What it takes to serve a model.

GPU Graphics processing unit
A chip built for doing many simple calculations at once. Made for game graphics, it suits models because they are mostly large matrix multiplications. GPU compute →
CUDA
Nvidia’s software layer for running calculations on its GPUs. Most machine-learning tools are built on it.
Inference engine
Software that loads a model and serves it to many users efficiently. vLLM is a popular open-source one.
KV cache
Saved attention results for the text already processed, so each new token does not redo all the earlier work. KV cache →
Quantization
Storing weights with fewer bits each, for example 8 instead of 32. The model gets smaller and faster and loses a little accuracy.
Speculative decoding
A speed-up: a small model drafts several tokens ahead and the large model checks them in one go.
