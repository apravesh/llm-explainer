SAME MACHINE, FIVE CHANGES

What changes from the text transformer

Blocks of attention followed by an MLP, residual connections, many heads: all of that is the same. These are the differences, in the order you meet them in the diagram.

01 / PATCHES AND EMBEDDING

Patches and embedding

A transformer works on a sequence of vectors. Text gets there through tokens. An image gets there by being cut into small squares.

Step 1 · Patchify

The image is divided into a grid of 16 × 16-pixel patches and read like a page: left to right, top to bottom. The 128 × 96 sample images here give 8 × 6 = 48 patches. A patch is to an image what a token is to a sentence. A larger image is not squeezed to a fixed size; it simply produces more patches.

Step 2 · Flatten

Each patch is 16 × 16 pixels with three colour values each, so it is already a list of 768 numbers. There is no vocabulary and nothing to look up.

Step 3 · Linear projection

One learned matrix, 1,024 × 768, turns those pixel values into a vector of 1,024 numbers, the width used through the whole encoder. Every patch goes through the same matrix. This plays the role of the token embedding table in the text model.

What is missing: position

GPT-2 adds a position vector to each embedding at this point. Pixtral's encoder adds nothing here. Where a patch sits is told to the model later, inside attention, by rotating Queries and Keys (2D RoPE, below). That is what lets it handle images of any size and shape.

02 / MULTI-HEAD SELF-ATTENTION

Multi-head self-attention

The step where patches read each other, so that a patch of feathers can know it sits next to an eye and above a branch. It works exactly as in the text model, with two changes.

Step 1 · Query, Key and Value

As in the text model, each patch's vector is multiplied by three learned matrices to make a Query (what this patch is looking for), a Key (what it offers to be found by) and a Value (what it hands over when picked). Each is cut into 16 heads of 64 numbers.

Step 2 · Rotate Query and Key by position different

Before they meet, the Query and Key are rotated by angles that depend on the patch's row and column. Two patches that are close together end up with a different dot product from two that are far apart, so the score knows about distance in both directions. Values are left alone. The 2D RoPE lab below lets you turn the vectors yourself.

Step 3 · Attention with no mask different

The three grids below show one head for the six patches in the explorer. Rows are the patch asking, columns the patch being looked at.

  • Dot product. Every Query is multiplied with every Key.
  • Scale. Scores are divided by √64 = 8. In the text model this is also where later tokens are set to −∞. Here nothing is hidden: an image is all there at once, so the whole grid stays.
  • Softmax. Each row is turned into weights that add up to 100%.

Illustrative values, built from the patches' colours and positions. In the real model each row runs over all 48 patches.

Compare with the text page: there the upper-right half of each grid is empty, because a token cannot see what comes after it. Here every cell is filled.

Step 4 · Mix the Values, then join the heads

The same as in text. The weights blend the Values into 64 numbers per head; the 16 heads are joined to make 1,024 again, passed through one more matrix and added to the patch's vector.

03 / GATED MLP

Gated MLP

After attention, each patch works on its own vector, as each token does in the text model. The shape is the same: widen, apply a simple function, narrow. Pixtral adds a second widened branch that acts as a gate.

Widen twice: 1,024 → 4,096

The patch's vector is multiplied by two different matrices, W₁ and W₃, giving two vectors of 4,096 numbers.

SiLU, then multiply

SiLU is applied to the first one; like GELU, it lets positive values through and pushes negative ones towards zero. The result is then multiplied, number by number, with the second vector. One branch proposes, the other decides how much gets through. This arrangement is called SwiGLU, and it is also what many recent language models use.

Narrow: 4,096 → 1,024

W₂ brings the gated vector back to 1,024 numbers, which are added to the patch's vector. One block is attention followed by this MLP; Pixtral's encoder stacks 24 of them.

04 / PROJECTOR

Projector

The text model ends by turning one vector into a probability for every token in its vocabulary. A vision encoder has no vocabulary to choose from. Its job is to describe the image to a language model.

Every patch is kept

In GPT-2 only the last token's final vector is used to pick the next word. Here all 48 final vectors matter: each one describes its patch, now informed by the whole image.

From 1,024 to 5,120

The language model that reads these vectors works with 5,120 numbers per token. A small projector, two linear layers with a GELU between them, resizes each patch's vector to that width. The result is one image token per patch.

Into the language model

The image tokens are placed in the prompt among the ordinary text tokens, with a marker at the end of each row of patches and at the end of the image so the model knows the image's shape. From there on, the language model treats them like any other token and attention does the rest. That model is the text transformer from the previous page, with its mask, its vocabulary and its next-token probabilities.

SAME TRANSFORMER. A DIFFERENT DESIGN GOAL.

From ViT to Pixtral

The first vision transformers (ViT) stayed closer to the text model. Pixtral's encoder is built to feed a language model, and that is where its choices come from.

Pack, don’t pad.

Pixtral packs image sequences together. A block-diagonal mask keeps attention inside each image; the language decoder combines them later.

A note on resolution. Flexible does not mean unlimited. Bigger images produce more patches, and dense encoder attention scales quadratically with the patch count. The demo uses small images to keep every number inspectable.
Where do the numbers on this page come from?

The structure and sizes are those of the vision encoder of Pixtral 12B as described by Mistral AI: 16 × 16 patches, 24 blocks, 16 heads, width 1,024, a gated feed-forward layer of 4,096, 2D RoPE in every attention layer, and a two-layer projector to the language model's width of 5,120.

The values drawn are illustrative. The attention dots are computed on this page from the average colour and the position of each patch, so that early blocks look at neighbours and later blocks look at similar-looking patches; they were not recorded from Pixtral. The vector bars are stand-ins. Only six of the 48 patches are shown at a time, and their attention weights are normalised among those six.

The 2D RoPE lab is exact: it applies the real rotation to small example vectors.
