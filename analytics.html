ARCHITECTURE / 04 · PARAMETERS

Where do a model's weights actually live?

“124 million parameters” is one number. This page takes it apart: which part of the transformer holds how many weights, how that changes for a mixture of experts or a vision encoder, and then what those weights cost to run.

What is counted, and what is left out?

Bias-free projections and RMSNorm-style gains (d each). A GELU MLP has two matrices (2·d·f); a SwiGLU MLP has three (3·d·f) and usually a smaller f. Grouped-query attention shrinks W_K and W_V to d × dkv, giving 2d² + 2·d·dkv. Real-model presets use published dimensions; because biases and a few small tensors are left out, totals land within about 1% of the official counts. The vision sketch follows Pixtral: 2D RoPE (no position weights) and a two-layer projector. The compute and GPU views below use their own dimension controls.

What to notice

In GPT-2, a third of the weights are the vocabulary table. 50,257 tokens × 768 numbers is 38.6 million weights before a single block. It is used twice, to turn tokens into vectors and to turn the final vector back into token scores, which is why small models share one table for both.

Inside a block, the MLP outweighs attention two to one. Attention is four d × d matrices (4d²). The MLP widens to 4d and comes back, which is 8d². Attention gets the name; the MLP holds most of the weights.

Bigger models are almost all blocks. Switch to Mistral 7B: the vocabulary tables shrink to a few percent, because blocks grow with d² × L while the tables grow only with d. Switch to Mixtral and the experts are nearly everything, yet each token runs only a quarter of them. Switch to Pixtral's encoder and there is no vocabulary at all; the projector takes its place.

02 / COUNT THE WORK

Compute

Compute is how much work it takes to run the model. Counting weights tells you how big a model is to store, not how much computing each token needs. Here is the diagram again, now with several tokens, for the model you picked in Capacity above, but now each badge counts FLOPs. The weights exist once; the work is paid once per token, which is why most formulas here start with n. Hover a part to see each multiplication and how they add up.

FLOPs are floating-point operations: one FLOP is one multiplication or one addition of two decimal numbers. Counting them is the usual way to measure how much work a model does, whatever chip it runs on. Using a weight once costs two FLOPs, one multiplication and one addition, so a matrix of d × d weights applied to one token costs 2 · d · d FLOPs (for GPT-2's WQ, 2 × 768 × 768 ≈ 1.18 million). That is where the 2 in every formula below comes from.

What to notice

Weights that are stored are not always weights that work. GPT-2's vocabulary table is a third of its weights. Reading a prompt uses it as a lookup, which costs nothing, and scoring the next token uses it once. Almost all the work is in the blocks.

Attention's mixing step has no weights and still costs the most on long prompts. Every token is compared with every other, so the work grows with n². Change the prompt from 1,024 to 8,192 tokens: the MLP's work grows 8 times, the mixing 64 times.

Writing is cheap per token because of the cache. Switch to “Write one more token”. The keys and values of earlier tokens are kept, so only the new token goes through the weights. That is why reading a long prompt takes a moment and the answer then streams out token by token.

03 / SPEND LESS

Optimizations

Capacity and compute are budgets, and models change specific parts of the architecture to spend less of them. These two changes reduce different parts of the cost of long prompts: how many tokens a layer keeps, and how much it keeps per token.

Long context: local and global attention layers

The problem. Compute showed that attention's mixing step compares every token with every earlier one, so its work grows with n². Memory has the same shape: to write quickly, every layer keeps the keys and values of every earlier token in the KV cache. At 1,000 tokens neither matters much. At 128,000 tokens both become the main cost of the model.

A global layer is the attention you already know: each token can look at all the tokens before it. A local layer uses a sliding window: each token can look only at the last w tokens. Its weights are exactly the same, WQ, WK, WV and WO; only the mask changes. So capacity stays the same and compute drops: the work is about n · w instead of n², and the layer needs to keep only the last w tokens in its cache.

Why not make every layer local? A local layer cannot reach past its window. Information from far back can still arrive, but only by being handed along: after k local layers it has moved at most about k · w tokens, and each hand-off can lose detail. Mistral 7B was built this way, with a window of 4,096 in every layer.

Mixing the two. Most of what a token needs is nearby: the current sentence, the last few paragraphs. So most layers can be local, with a global layer every so often to connect distant parts of the prompt directly, such as a question at the end with a fact 100,000 tokens earlier. Gemma 3 does this to reach a context of 128,000 tokens: 5 local layers with a window of 1,024 for every global layer. In the lab above that setting keeps about a sixth of the cache and of the comparisons of an all-global model.

The context window itself is unchanged. The model still accepts the same number of tokens; what shrinks is the cost of each layer that does not need to see all of them.

KV Cache and Grouped Query Attention (GQA)

The KV cache avoids redoing work. During generation, each transformer layer keeps the key and value vectors for tokens already processed. For the new token, it computes a new Q, K and V, appends K/V to that layer’s cache, and uses the new Q to attend to the available K/V history.

Why not cache Q? Earlier queries have finished their job: they computed attention for their own positions. Future tokens use their own queries, but reuse earlier keys and values. Old Q is not discarded because it changes—it is discarded because it is no longer needed. With causal attention and an unchanged prefix and model, earlier K/V stay unchanged.

The cache stores sequence-specific intermediate vectors, not model weights. Its size grows with the retained context. Local attention can keep fewer tokens; grouped-query attention keeps fewer K/V heads per token.

Same width, separate attention — what changes under the hood?

For query head i in group g, with the same mask as before:

Ai = softmax(qi KgT / √dh + mask)
oi = Ai Vg

Kg and Vg are shared; qi, Ai and oi are per query head. Separate softmax computations can give different distributions over the very same positions, not necessarily identical outputs. Each q, key, value and head output here has dh entries; A has one entry per cached position. Concatenate the Hq head outputs and apply WO as usual.

For input width d, WQ still has shape d × (Hq · dh), but WK and WV each have shape d × (Hkv · dh). Fewer heads, not narrower heads. This is an architecture choice, not a lossless switch for an arbitrary trained model; quality depends on training.

The ratio holds at equal cached length, head width and precision. Sum the bytes across layers and sequences for a model's logical KV payload. Local windows and head sharing can be combined. Attention mixing still runs for every query head; kernels, hardware, memory traffic and workload determine actual speed. Allocator overhead, temporary K/V replication and other memory are excluded.
