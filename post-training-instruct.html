Same predictor.

Supervised fine-tuning (SFT) continues training a pretrained model on examples of desired responses. It still predicts the next token—but the data now demonstrates how to answer.

01 / CHAT TOKENS

A conversation becomes
one token stream.

A chat template inserts boundaries around messages so the model can distinguish roles, content and endings. Special tokens have reserved IDs and learned embeddings—not magical “instruction” behavior. The model learns their use from training examples. [1]

Are these the same tokens in every model?

No. For example, Mistral-7B-Instruct-v0.1 wraps user messages with [INST] and [/INST]; the template above is intentionally fictional. Words and punctuation are kept whole for readability. Some templates use role-specific tokens; others surround ordinary role names with special delimiters. Models may distinguish end-of-message, end-of-turn and end-of-sequence. Use the tokenizer and chat template matching the checkpoint, including its generation prefix. A system message, when supported, is serialized too. Avoid adding duplicate beginning/end tokens. Introducing new special tokens requires matching embedding/output entries and training—not just typing their spelling. Boundaries also are not a security barrier against prompt injection. [1]

02 / DEMONSTRATIONS, NOT JUST DOCUMENTS

Collect the behavior
you want to teach.

Each record pairs an instruction and context with a good response, sometimes across multiple turns. Sources include human demonstrations, suitable existing datasets, and generated answers that are filtered or reviewed. Quality and task coverage matter—not just the number of records. [2] [3]

From candidate answers to a training setFour hand-authored illustrations · no data collected

What does a stored record look like?
{"messages": [
  {"role": "user", "content": "Say hello."},
  {"role": "assistant", "content": "Hello!"}
]}

These are structured messages, not the final model input. The training pipeline applies the chat template, tokenizes, and marks which target tokens receive loss. At scale, use task/source diversity, annotation guidelines, privacy checks and held-out evaluations. Synthetic answers can carry the teacher’s errors and biases; review and filtering help but do not guarantee correctness.

03 / SAME NEXT-TOKEN OBJECTIVE

Read the prompt.
Learn from the response.

Pretraining typically scores nearly every valid next token in broad text. A common SFT setup scores only assistant responses. The prompt still enters causal attention as context; a loss mask determines which predictions contribute to the objective. Assistant-only loss is a choice, not the definition of SFT. [4]

Does masking the prompt stop gradients through it?

No. Its own next-token targets can be unscored, while assistant predictions still depend on prompt representations through attention. Gradients from those predictions can flow through the prompt-side computation to shared weights. A loss mask is not an attention mask: both modes still use causal attention.

For each vocabulary logit zⱼ, ∂L/∂zⱼ = mₜ · (pⱼ − 1[j = target]) / N, where N is the number of scored tokens. The displayed probabilities are an illustrative normalized distribution, not model output. The slider changes one target probability and redistributes the remainder equally among other vocabulary entries. We compute loss and this derivative, but do not simulate a weight update.

What stays the same?

Token embeddings, causal transformer, next-token cross-entropy, backpropagation and an optimizer. Training uses the correct preceding answer tokens—not sampled responses.

What changes?

Start from a pretrained checkpoint, use curated demonstrations, and choose the loss mask. Often less data and a smaller learning rate. Update all weights or train adapters; the tokenizer is usually reused.

What SFT is not

No reward model or policy-gradient objective is needed. SFT imitates target responses. It does not guarantee truthfulness, safety or perfect instruction-following.
