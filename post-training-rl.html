TRAINING / 03 · LEARNING FROM FEEDBACK

Try a few answers.
Learn which work.

SFT copies a given answer. Here there is no answer to copy: the model tries several answers itself, a checker scores them, and the ones that scored above the group’s average become more likely. REINFORCE is the simplest version; GRPO and DPO are two widely used refinements. [1]

Where do rewards come from? Does GRPO need another model?

A verifier can check arithmetic answers or run code tests; other tasks may use a learned reward model or human feedback. GRPO uses the group’s rewards as a baseline instead of training a separate value/critic model. A reward model is optional—not the same thing as a critic. The reward need not be differentiable: gradients flow through the policy’s log-probabilities, not through the answer checker. A poor reward can teach reward hacking instead of the intended behavior. [1]

02 / THREE WAYS TO LEARN FROM FEEDBACK

Try four answers.
Reward the better half.

Start with REINFORCE, the simplest method: one model writes four answers, the better-than-average ones become more likely, repeat. GRPO adds a frozen copy, a probability ratio and clipping so one group can safely be reused for several updates; three updates is our teaching choice—not a GRPO requirement. DPO skips trial and error and learns from pairs where one answer is marked as preferred. [2]

What math does GRPO use?

1. Compare within the group. Aᵢ = (rᵢ − mean reward) / reward standard deviation. Above-average answers have positive advantage; below-average answers have negative advantage. Equal rewards give zero advantage in this demo. We use population standard deviation; implementations may use another convention or normalization.

2. Compare new and old probabilities. ρᵢ = πθ(answerᵢ | prompt) / πold(answerᵢ | prompt). Both policies evaluate the same sampled answer. The denominator and advantages stay frozen across this group’s updates.

L = −meanᵢ min(ρᵢ Aᵢ, clip(ρᵢ, 0.8, 1.2) Aᵢ)

3. Backpropagate, then update. Minimize this loss with SGD: θ ← θ − 0.15 ∇θL. The min/clip removes the incentive for an already-large move in the favored direction. It is not a hard bound on every probability change; shared parameters can still move it.

Here θ contains just three answer logits. For an unclipped term, ∂L/∂θⱼ = −Aᵢρᵢ(1[j = answerᵢ] − πθ(j)) / 4, summed over rollouts. Clipped plateaus contribute zero gradient. A zero loss value at the initial ratio 1 does not imply zero gradients.

How does GRPO extend to a real LLM?

Real completions have many tokens. A response-level advantage can be applied to its generated tokens, with token-level probability ratios and a chosen loss normalization. Prompt tokens provide context, not sampled actions. A causal forward pass evaluates the recorded completions, and backpropagation updates transformer weights or adapters. There are usually many prompts per batch.

The original GRPO objective also includes a KL penalty to a reference policy. This teaching variant sets its coefficient β = 0 and omits the reference model. If used, a reference policy is an anchor (often fixed), distinct from the old rollout policy that refreshes. Reward normalization, KL, clipping and update schedules vary across implementations. [1] [2]

What math does REINFORCE use?

1. Compare with a baseline. Aᵢ = rᵢ − mean reward. Above-average answers get a positive number, below-average ones a negative number. If every reward is equal, every Aᵢ is 0 and nothing is learned from this group.

L = −meanᵢ Aᵢ · ln πθ(answerᵢ | prompt)

2. One gradient step. θ ← θ − 1.0 · ∇θL. For the three answer logits, ∂L/∂θⱼ = −meanᵢ Aᵢ (1[j = answerᵢ] − πθ(j)). Then the group is thrown away and the updated model writes a new one.

The baseline does not change the expected gradient; it only reduces its noise. REINFORCE uses each group once, so it needs many fresh samples. GRPO’s extra machinery exists to reuse a group for several updates safely. In a real LLM a response has many tokens: the same Aᵢ multiplies the log-probability of every generated token.

What math does DPO use?

1. Start from preferences, not rewards. Each record has a prompt, a preferred answer and a rejected answer. Nothing is sampled and no reward function is called during training.

2. Measure how much the model has moved toward the preferred answer, relative to a frozen reference copy: m = [ln πθ(chosen) − ln πref(chosen)] − [ln πθ(rejected) − ln πref(rejected)].

L = meanᵢ −ln σ(β · mᵢ), β = 1

3. One gradient step. θ ← θ − 1.0 · ∇θL. Each pair pushes its chosen answer up and its rejected answer down with strength 1 − σ(β·m), which fades as the model agrees with the preference.

DPO is usually grouped with preference or alignment tuning rather than reinforcement learning: it is derived from an RL objective with a KL penalty to the reference, but trains like supervised learning on a fixed dataset. The reference copy never refreshes. [3]

Refresh ≠ save ≠ deploy

Training weights change each optimizer step. Rollout workers need refreshed weights, which can be copied directly without saving a file. Durable checkpoints and production deployments can follow different schedules.

Improvement is not guaranteed

A group can be all correct or all wrong and provide no relative signal. Better reward on one prompt is not general capability. Evaluate held-out tasks, safety and reward exploits before promoting a checkpoint.

What is saved in practice?

Inference needs model weights plus the matching config, tokenizer and chat template. Faithful training resumption also needs state such as the optimizer, scheduler, random generators and training progress.
